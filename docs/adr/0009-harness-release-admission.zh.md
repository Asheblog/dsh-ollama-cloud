# ADR 0009 — 以「契约同一」证明来接纳 Harness 发布

状态：已采纳（2026-11-03）。

## 背景

桌面端跟随一条发布通道，Harness 的移动与本插件无关：`0.5.0` 对着 `rc.3` 发布后
第四天来了 `0.2.1-rc.4`，第十天来了 `0.2.1-rc.5`。本包在两处回应这种移动——
`dsh.compatibility.dshReleases` 记录逐版本结论，`engines.dsh` 声明下限——
而两者都是关于「本构建从未在其上跑过的那个版本」的断言。

这里已经失败过两种回答方式：

- **按范围接纳。** `0.4.0`–`0.4.2` 的 `engines.dsh` 无上界，于是放行了每一个
  `0.2.1` 版本，包括那个改了 composition 启动服务名的版本。结果一条 required 行
  永远等待、整个启动失败（[ADR 0008](0008-composition-patch-follows-the-startup-service.zh.md)）。
- **在用户报障前什么都不声明。** 插件静默过期，第一个信号是某个人的安装坏了。

在「发布号变了」与「契约变了」之间还有第三种答案，而且它才是常态：多数班次上除了
`version` 什么都没变。本插件每个版本真正要回答的问题很窄——*本构建所编译依赖的东西
变了吗？*——而它可以从已发布的 tarball 里判定。

## 决策

当 `pnpm run check:contract <已接纳版本> <候选版本>` 对本包声明的每一个
`@deepseek-ai/dsh-*` 包都报出**契约同一**时，接纳该候选版本。契约同一的含义，逐包：

1. 出厂文件集合完全一致；
2. 除 `package.json` 外每个文件逐字节一致；
3. 把 `0.2.1-rc.N` 这段发布号归一化后，`package.json` 深度相等；
4. 发布号确实不同——两侧被钉在同一版本的包记为问题而非通过，因为它什么都没比较。

满足后，接纳动作是四处改动，没有一处是源码：把 `devDependencies` 移到候选版本
（使 `typecheck` 与 `test` 跑在「构建将被装进去」的那份契约上）、把候选版本写进
`dsh.compatibility.dshReleases`、把 `pnpm-workspace.yaml` 里的 release-age 豁免
改为新版本（它们写的是精确版本，会随钉子一起过期）、在 changelog 记一笔。
`engines.dsh` 只在下限本身移动时才改。

若比较器报出漂移，这个发布就**不是**版本支持同步：漂移的文件就是议程，代码、bundle
patch 或 pi-ai 代际可能得先跟上，然后才谈声明。

只归一化「发布号」是刻意的。其它任何清单差异都会留下——`@deepseek-ai/cordis` 的一个
minor、一个改名的传递依赖、一个新增的 `exports` 条目——而这正是「只对本插件 import
到的模块做表面 diff」看不见的那类变化。

## 影响

- 每个版本一条命令，需要网络与 `tar`，因此不进 `pnpm check`——那条门必须能离线且确定。
- 离线守卫不变且互补：`tests/composition.test.ts` 把 bundle patch 对照已装
  composition、把发布矩阵对照已装版本，`check:pi-ai` 对照两侧 pi-ai 区间。它们覆盖
  「本构建被钉在什么上」，比较器覆盖「即将被钉在什么上」。
- 判据是可执行的，下一次抬版无法再把它重新推导成另一个样子。
- 本次在线的两侧都验证过：`rc.3 → rc.5` 与 `rc.3 → rc.4` 通过，而
  `0.2.0-rc.2 → 0.2.1-rc.5` 在 `dsh-web-app` 的 `cordis.patch.yml`、新增的 `locale/`
  载荷与 peer 表上失败——正是当年打断 `0.4.0` 的那次移动。

被否掉的方案及理由：

1. **只按范围接纳。** `0.4.0`–`0.4.2` 的做法，后果见 ADR 0008。
2. **用户报障前什么都不声明。** 通道自己会往前走，静默与正常在启动失败前无法区分。
3. **抬 `devDependencies` 后只信 `pnpm test`。** composition 测试守的是被补丁的那一行
   与矩阵内部一致性；它看不见收窄的类型，也看不见本插件尚未 import 的包里的传递移动。
4. **把比较留在 `.tmp` 里当一次性脚本。** 判据一旦住在某人的临时目录，就会被重新推导
   ——而且推导成另一样，这正是当年 `rc.1` 被标为兼容、补丁却还写着 `webRuntime` 的成因。
5. **把比较器塞进 `pnpm check`。** 它需要 registry，门会在离线或镜像抖动时失败；发布
   检查也不该让每次提交都付账。
