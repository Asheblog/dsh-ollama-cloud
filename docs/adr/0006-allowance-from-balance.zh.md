# ADR 0006 — 额度取自 `/api/balance`，不再是 `/api/usage`

Status: accepted (2026-10-12)

取代 [ADR 0003](0003-usage-ui-in-host-slots-over-the-connection-channel.md) 中关于端点的假设；
该 ADR 关于**面板渲染在哪里**与**如何拿到需要凭据的数据**的决定不受影响。

## Context（背景）

`0.2.0` 的用量面板（ADR 0003）建立在 `GET <native base>/usage` 之上，其响应携带
`limits` 对象：每个窗口一个已用比例（`usage`）、每模型请求数（`models`）以及重置时刻。
当时端点确实这么答，面板就是照这个形状写的。

到 2026-10-12，端点已不再这么答。在真实账号上实测：

- `GET https://ollama.com/api/usage` 现在答的是 Ollama 已公开文档化的请求/Token/费用时间序列
  （[cloud usage](https://docs.ollama.com/api/cloud-usage)）：`range`（`24h`｜`7d`｜`30d`）、
  `scope`、`granularity`、`from`、`until`、`totals`、`buckets`，每个 bucket 带
  `request_count`——在会报告费用的套餐上还带 `usage_usd` 与 Token 数。里面**没有** `limits`、
  没有按窗口的额度、也没有任何按模型的拆分；上游把「按模型 / 按 API Key 的拆分」列为
  "coming soon"。
- 额度搬到了 `GET https://ollama.com/api/balance`：

  ```json
  {
    "included": {
      "session": { "remaining_percent": 95.55, "resets_at": "2026-10-12T03:00:00Z" },
      "weekly": { "remaining_percent": 99.21, "resets_at": "2026-10-19T00:00:00Z" }
    },
    "purchased": { "balance_usd": 1.59332 }
  }
  ```

也就是说：面板一直在读一份已经不复存在的契约。解码器拒绝了它**真正收到**的响应体——
`malformed usage response (body keys: range, scope, granularity, from, until, totals, buckets)`
——卡片因此显示「读取用量失败」，侧栏显示「额度不可用」。面板不是连不上，而是**看不懂已经收到的答案**。

这件事没被任何测试拦住，原因是结构性的而非偶然的：整套测试pinned的都是 mock，而 mock 与它所喂的
代码出自同一个假设。解码器可以既全绿、又对它读的端点完全判断错误。

## Decision（决定）

1. **额度从 `/balance` 读。** `usage.ts` 请求 `GET <native base>/balance`，把
   `included.<window>.remaining_percent`（0–100，表示**剩余**）解码为面板 meter 所画的
   已用比例，并把 `resets_at` 归一化为 ISO。展示 id 仍为 `monthly` / `session` / `weekly`。
   端点报告什么就显示什么：套餐没有的窗口就是不出现，面板没有座位的 id 则忽略，**而不是**套到相邻窗口的
   标签下画出来。三个座位属于插件；在座位之内，成员资格由端点回答——只报告三个之外窗口的套餐会得到
   可诊断的失败而不是空白面板，第四个 id 需要什么见下方「后果」。
2. **刻意不读 `/api/usage`。** 它报告的是量，而面板计量的是额度，`/api/usage` 根本回答不了
   这个问题。已否决：**两个都读**并把请求数并排显示——那是一个有自身设计问题的新功能
   （对永远撞不到上限的用户，请求数意味着什么？取哪个 range？并到哪个窗口旁边？），不是本次修复。
   已否决：**把 `/api/usage` 当作额度的降级来源**——承载不了该值的降级路径，只会让人自信地显示错数字。
3. **超出 0–100 的读数夹取（clamp），窗口缺失不算错误。** `100.4` 是百分比的舍入产物，不是窗口丢失；
   因为它把面板清空，反而会藏起一个其实正常的读数。`remaining_percent` 不是有限数的窗口会被丢弃；
   整个响应体解不出任何窗口才是失败，并且要在报错里列出它看到的键——「端点换形状了」必须能从
   一行日志诊断出来，而这正是本次事故所需要的。
4. **按模型的拆分直接删除，而不是留空。** 旧形状每窗口带 `models`，当前契约没有。wire 窗口现在只有
   `{ usage, resetsAt? }`，卡片的「用量来源」区块、它的两个文案键、对应 CSS 以及解码器里读该字段的
   那段代码一并删除。留着一个端点已不再发送的可选字段，恰恰会重建本 ADR 要消除的「幽灵契约」那类问题
   ——该字段永远不可能非空，所以删掉它对用户可见行为毫无影响。等 Ollama 真的发布按模型的拆分时，
   它会作为**从真实答案出发设计**的功能回来。

   这次删除同样覆盖旧形状曾使用过的重置时刻写法：`reset_at`、`reset`、`resetsAt`、epoch 秒与毫秒、
   `reset_after_seconds`。当前契约把 `resets_at` 作为 ISO 时刻给出；完全不带时刻的窗口仍保留条目、
   退回到文档化周期。容忍端点根本不再发送的写法，只会带来风险（读错的时刻就是错的重置行）而带不来价值。
5. **不上屏 `purchased.balance_usd`。** 这是该端点确实报告、而本面板不展示的事实。这是范围决定，
   记在这里是为了让它读起来像一个决定：美元余额不是「额度百分比」，它需要自己的呈现决定
   （格式、币种、与两个百分比的排布关系），不适合塞进一次修复里顺手做。
6. **真实契约由脚本检查，而不只靠 mock。** `scripts/check-live-allowance.mjs`（`pnpm run check:live`）
   把真实端点依次喂给宿主解码、wire 投影和浏览器半侧自己的解码器，并打印每个窗口的剩余份额。
   它需要账号密钥与网络，所以不进 `pnpm check`；它的用途是在怀疑端点变动时手动跑，而它正是能拦住
   本次事故的那项检查。它把三种漂移分开报告——读取失败、端点根本不报额度（404）、份额超出 0–100——
   因为「解码坏了」和「端点不再是云端端点」是两种不同的发现。

## Consequences（后果）

- 两个界面重新计量真实的剩余份额，旁边是端点自己给出的重置时刻。
- 原本就正确的受支持语义不变：`404` 仍是「此端点不上报云端用量」（本地 / 自建服务器），
  `401`/`403` 仍是凭据被拒，传输失败照旧明说。变的只是在**读取成功**之后如何解码。
- 面板展示的是套餐实际拥有的窗口。本次修复所依据的账号是旧套餐，报告 session 与 weekly 两个窗口、
  没有 monthly，所以它画两条 meter；会报告 monthly 窗口的套餐无需改代码就会多出第三条——因为 id 相同，
  而成员资格由端点回答。
- 面板只读三个 id（`session`、`weekly`、`monthly`），因为它只有三个座位；而座位不只是键，它意味着
  标签、重置周期和显示次序。所以第四种窗口需要一次客户端改动；在有之前，只报告三个之外 id 的套餐
  会带着它发来的 id（`included keys: …`）显式失败，而不是画一条没有标签的 meter。这是**已知限制**
  而非疏漏：把未知 id 套到相邻窗口的标签下渲染，等于把一个错数字放到屏幕上，比一次能自我说明的失败更糟。
- 内部快照不再携带每模型计数，wire 窗口不再携带 `models`。读本插件通道的第三方 UI 若**强制要求**
  该字段会显式报错，而不是静默什么都不渲染——而且自端点停止发送它以来，那些 UI 本来就什么都渲染不出来，
  所以没有可观察的损失。
- 端点报告了窗口但没给重置时刻时，标签沿用文档化的周期（session 5h、weekly 7d、monthly 30d），
  而不是留一行空白。
- mock 单测仍然 pin 解码规则；真实脚本 pin 规则所依据的那个假设。这是两个不同的问题，
  而本次事故是第二个。
